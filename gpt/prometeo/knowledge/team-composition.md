# Team Composition

## Team Size Guidelines

### Solo Developer (1)
**Good for:**
- Personal projects
- Simple websites
- Prototypes
- Learning projects

**Challenges:**
- Knowledge silos
- No code review
- Limited capacity
- Burnout risk

### Small Team (2-5)
**Composition:**
- 1-2 Full-stack developers
- 1 Frontend specialist  
- 1 Backend/DevOps

**Good for:**
- MVPs
- Startups
- Simple products
- Fast iteration

**Pros:** Fast decisions, close collaboration
**Cons:** Limited expertise depth

### Medium Team (6-12)
**Composition:**
- 2-3 Frontend developers
- 2-3 Backend developers
- 1 DevOps engineer
- 1 QA engineer
- 1 Tech lead

**Good for:**
- Growing products
- Multiple features in parallel
- Established companies

**Pros:** Specialized roles, better quality
**Cons:** More coordination needed

### Large Team (15+)
**Composition:**
- Multiple feature teams
- Platform/infrastructure team
- QA team
- Security specialists
- Architects

**Good for:**
- Enterprise products
- Complex systems
- Multiple products

**Pros:** Deep expertise, parallel work
**Cons:** Communication overhead

## Team Composition by Project Type

### E-commerce Platform
**Team (8 people):**
- 2 Frontend (storefront + admin)
- 2 Backend (API + payments)
- 1 DevOps (deployment + monitoring)
- 1 QA (testing + automation)
- 1 Mobile developer (app)
- 1 Tech lead

### SaaS Dashboard
**Team (6 people):**
- 2 Frontend (React + charts/analytics)
- 2 Backend (API + data processing)
- 1 DevOps
- 1 Full-stack (integration work)

### Mobile App
**Team (5 people):**
- 2 Mobile developers (iOS + Android or React Native)
- 1 Backend developer (API)
- 1 DevOps
- 1 Designer/Frontend

### Internal Tool
**Team (3 people):**
- 1 Full-stack developer
- 1 Backend developer  
- 1 Part-time DevOps/IT

## Role Definitions

### Tech Lead
**Responsibilities:**
- Technical architecture decisions
- Code review oversight  
- Team mentoring
- Stakeholder communication

**Should be:** Senior+ level, good communicator

### Senior Developer
**Responsibilities:**
- Complex feature development
- Junior developer mentoring
- Technical design
- Code quality standards

**Ratio:** 1 senior per 2-3 junior/mid developers

### Junior Developer  
**Responsibilities:**
- Feature implementation under guidance
- Bug fixes
- Learning and growing
- Testing

**Support needed:** Mentoring, pair programming

## Team Collaboration Patterns

### Feature Teams (Recommended)
**Structure:** Cross-functional team per feature
**Members:** Frontend + Backend + QA per team
**Benefits:** Ownership, faster delivery
**Good for:** Medium+ teams

### Component Teams
**Structure:** Teams by technology layer
**Members:** All frontend devs in one team
**Benefits:** Deep specialization
**Good for:** Large products with stable architecture

### Squad Model (Spotify)
**Structure:** 6-8 person autonomous teams
**Members:** Full-stack capability per squad
**Benefits:** Independence, innovation
**Good for:** Large organizations

## Hiring Strategy

### Early Stage (First 5 hires)
1. **Full-stack generalist** - Can do everything
2. **Strong frontend** - User experience critical
3. **Strong backend** - Scalability and reliability  
4. **DevOps/Infrastructure** - Deployment and monitoring
5. **Senior developer** - Mentorship and architecture

### Growth Stage (Next 10 hires)
- **Specialists** in key technologies
- **QA engineer** for quality
- **Mobile developers** if needed
- **More senior developers** for mentorship

### Scale Stage (20+ people)
- **Architects** for system design
- **Security specialists**  
- **Data engineers**
- **Platform teams**

## Remote vs Co-located

### Remote Teams
**Pros:**
- Access to global talent
- Cost savings
- Flexible schedules

**Cons:**
- Communication overhead
- Time zone challenges
- Culture building

**Requirements:**
- Strong documentation culture
- Async communication tools
- Regular video calls
- Clear processes

### Hybrid Teams
**Best practices:**
- Core hours overlap
- In-person quarterly meetups
- Strong remote-first processes
- Equal treatment of remote/local

- [ ] Independent feature delivery
- [ ] Mentor newer team member

- [ ] Technical design participation

## Common Team Issues

### Communication Problems
**Symptoms:** Duplicate work, missed requirements
**Solutions:** Daily standups, clear documentation

### Skill Gaps
**Symptoms:** Bottlenecks, knowledge silos  
**Solutions:** Cross-training, pair programming

### Productivity Issues
**Symptoms:** Missed deadlines, low morale
**Solutions:** Process improvement, workload balance

### Quality Problems
**Symptoms:** Bugs in production, tech debt
**Solutions:** Code review process, testing standards
